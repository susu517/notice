手动输入内容并提炼

把通知文字整段贴进来。点提炼先在你这台设备上用规则立刻出一版（分类、星级、时间、要点），同时把内容排进云端 AI 队列；AI 处理完，卡片会自动换成 AI 版（能纠正错字、按意思归纳）。原文只在你点提炼后发给自己的云端，不上传到别的地方。

识别网址

贴一个通知文章链接，自动抓正文并按同一套口径提炼。走 GitHub 抓取，大约等 1 分钟。

抓不到正文时会显示抓到了多少字，方便判断是链接不对还是正文在附件里。

粘贴公众号文章链接

把公众号文章的链接贴进来，一行一条。可以先识别一下这些链接分别是什么、能不能自动抓，再存成待处理清单。

说明：微信不允许任何服务器直接抓取公众号正文（实测带微信 UA、浏览器 UA、Referer 模拟，都会被转到「环境异常」验证页）， 搜狗微信搜索与第三方 RSS 通道同样失效。所以公众号这里只留链接，正文需要你从微信复制后，粘贴到上方「正文内容」里提炼。

推送邮箱

填一次就行。之后点每条通知右上角的「推送」，手机会直接打开邮件 App，标题和内容都已经填好，按发送即可。不需要申请 GitHub Token。

只存在这台手机里，不会写进网页。

推送

邮件推送：每 30 分钟检查一次，有新的重要通知才发信，没有新通知不发。

收件邮箱和发件邮箱在 GitHub 仓库的 Settings → Secrets 里配置（SMTP_USER / SMTP_PASS / MAIL_TO）。

云端同步

填一次 Supabase 的地址和 anon key。连上以后，收藏和自加的常用网址会存到云端，清缓存、换手机、换电脑都自动回来。

备份与恢复

把留档、本机存的收藏、自己加的常用网址一起存成一个 JSON 文件。换手机、清浏览器数据、手滑清空之后，导入这个文件就能全部找回来。

导出后文件在手机的「下载」目录；恢复时点「导入备份」，选那个 JSON 文件即可。

监视范围

正在监控的网址在「常用网址」板块，那里也能直接加新栏目。

新加的栏目第一次检查只登记已有通知，不推送历史，从第二次才开始推新的。

留档与删除

数据存在仓库的 data/notices.json 里，每次抓完自动提交，不会丢。

留档库的「删除」只是移进回收站（本地记录）；回收站的「彻底删除」会同时把这条从仓库的 data/notices.json 里删掉，之后不会再出现。

彻底删除需要 Token 勾上 Contents: Read and write 权限；没填 Token 时只在本机隐藏。
