# 学院信息筛选助手

自动盯着学院官网的几个栏目，一有新通知就按你定的口径判断、提炼、留档、推送邮件，并在网页上随时可看。

**不用你电脑开机，全部在 GitHub 上免费跑。**

---

## 一小时能装完的三步

### 第 1 步：建仓库（3 分钟）

1. 打开 https://github.com/new
2. **Repository name** 填 `notice`（或你喜欢的名字）
3. 选 **Public**（公开仓库，定时任务才不限时长、网页托管才免费）
4. 点 **Create repository**

### 第 2 步：把文件传上去（5 分钟）

1. 在新建的仓库页面点 **uploading an existing file**（或 `Add file` → `Upload files`）
2. 把解压出来的这些文件/文件夹**全部拖进去**：
   - `screener.js`
   - `crawler.js`
   - `render.js`
   - `monitor.js`
   - `config.json`
   - `package.json`
   - `package-lock.json`
   - `README.md`
   - `data/` 文件夹（里面有 notices.json、state.json）
   - `docs/` 文件夹（里面有 index.html）
   - `.github/` 文件夹（里面有 workflows/monitor.yml）
3. 底部 Commit changes 里填 `初始化`，点 **Commit changes**

> 注意：`.github` 是隐藏文件夹，Windows 里以 `.` 开头的文件夹可能看不到。
> 如果拖拽时漏掉了它，改用「Add file → Create new file」，文件名填 `.github/workflows/monitor.yml`，把本地那个文件内容粘进去保存即可。

### 第 3 步：打开网页和定时任务

1. **网页**：仓库 **Settings** → 左侧 **Pages** → Source 选 **Deploy from a branch** → Branch 选 **main**、目录选 **/docs** → **Save**
2. 等 1~2 分钟，访问 `https://你的用户名.github.io/notice/`
3. **定时任务**：仓库 **Actions** 标签 → 左侧「学院信息自动检查」→ 点 **Enable workflow**（如果没自动启用）
4. 想立刻试一次：点右侧 **Run workflow** → **Run workflow**

## 它每 2 小时做什么

1. 打开 `config.json` 里配置的每个栏目页
2. 跟仓库里已记录的链接比对，**只有没见过的才算新**
3. 新链接逐条抓正文 → **先交给 AI 读懂语义判断要不要留**（AI 不可用时自动退回规则判定）→ 提炼
4. 保留的写进 `data/notices.json`，重新生成 `docs/index.html`
5. 有新增就发一封邮件到你手机

**第一次运行只登记基线**：把官网上现有的通知链接先记下来，不抓正文、不推送。从第二次开始才推新的。这样你上线时不会收到一堆历史通知。

基线有一个保护：**如果第一次运行时全部栏目都抓取失败**（网络抖动、学校网站临时打不开），这一轮不会算作基线建立，下一轮会自动重新登记。否则第二轮会把整个历史列表当成新通知，一次给你推几十条。

`data` 目录下的文件**不用手工预建**，程序第一次跑就自己生成。如果你已经手工建了、里面是空的 `{}` 或 `[]`，程序也会自动补齐结构，不会卡住。

## AI 提炼（可选，不配也能跑）

判定有两条路，AI 优先，规则兜底：

- **AI 读懂语义**：把标题和正文交给智谱 GLM-4-Flash，让它判断这条要不要学生处理、归哪一类、几星、要做什么。优点是排版乱、正文夹在附件说明里也能判断。
- **规则兜底**：AI 没配密钥、超时、限流、返回格式不对，都会自动退回正则规则，同一套口径照常出结果，不会因为 AI 挂了就漏掉通知。

AI 还会给每条拟 2 到 3 个短标签（如 `#四六级` `#缓考` `#大创` `#三方协议`），显示在分类标签旁边，扫一眼就知道讲什么。标签会去掉井号、超过 8 个字的丢弃，模型乱给也不会出问题。规则兜底判定的条目没有标签。

时间字段**始终由规则计算**，不用 AI 输出。原因是你定的格式是「报名 11月12日 — 11月18日；初赛 2026年11月20日；决赛 2026年12月5日」这种带标签并列，模型每次写法都不一样，会破坏这个格式。

配置方法：

1. 打开 bigmodel.cn，手机号注册，进控制台 → API Keys → 创建，复制密钥
2. 仓库 Settings → Secrets and variables → Actions → New repository secret
3. Name 填 `ZHIPU_KEY`，值粘贴密钥

不配也能用：没填 `ZHIPU_KEY` 时日志会写「AI 没有配置」，全部按规则判定，网页和邮件照常工作。

想彻底关掉 AI，把 `config.json` 里的 `"ai": { "enabled": true }` 改成 `false`。

### 出问题会发邮件告警

出故障时不看 Actions 日志也能知道，以下三种情况会发一封标题为「运行异常」的邮件：

- 本轮所有栏目都抓取失败（站点打不开、栏目地址改版）
- 部分栏目抓取失败（会列出是哪几个、什么原因）
- 重试队列积压超过 10 条

同类告警**一天最多一封**，避免刷屏。栏目本身没内容（比如实验管理长期为空）不算故障，不会告警。

### 失败不会丢

AI 调用失败的通知不会当成已处理。正文也抓不到、规则也判不出东西的那种，会进 `data/retry_queue.json`，下一轮优先重试，最多重试一天，超过才放弃并写进日志。

日志里能看到每条走的是哪条路：

```
AI 提炼 3 条，规则兜底 1 条，AI 判为不保留 2 条
本轮有 1 条没处理成，已放入重试队列，下一轮优先重试。
```

网页上每张卡片来源行也会标出「AI 提炼」或「规则提炼」，能直接看出这条是谁判的。

## 想收邮件推送（可选）

不配也行，网页照常更新。想收邮件就加 5 个 Secret：

仓库 **Settings** → **Secrets and variables** → **Actions** → **New repository secret**，依次添加：

| Name | 填什么 | 例子 |
|---|---|---|
| `SMTP_HOST` | 邮箱服务商 | `smtp.qq.com` |
| `SMTP_PORT` | 端口 | `465` |
| `SMTP_USER` | 你的邮箱地址 | `123456@qq.com` |
| `SMTP_PASS` | 邮箱**授权码**（不是登录密码） | 在 QQ 邮箱设置里生成的 16 位码 |
| `MAIL_TO` | 收件邮箱（可填自己） | `123456@qq.com` |

QQ 邮箱授权码的位置：QQ 邮箱网页版 → 设置 → 账户 → POP3/IMAP 服务 → 开启后生成授权码。
安卓手机装 QQ 邮箱 App 也能生成：设置 → 账号 → 添加账号 → 手动设置 → 获取授权码。

### 填完先测一下，别等

Secret 加完后，点仓库 **Actions** → 左侧 **测试邮件推送** → 右侧 **Run workflow** → 再点 **Run workflow**。

半分钟后刷新这一条记录，能看到：

- 绿色对勾 + 日志里 `发送成功 → 你的邮箱` → 配置正确，去收邮件
- 红色叉 + `发送失败：Invalid login` → 授权码错了，或者填的是登录密码
- 红色叉 + `缺少 SMTP_USER` → Secret 名字拼错了，注意大小写必须是 `SMTP_USER`

收到测试邮件就说明推送通了。以后每 2 小时检查一次，有新通知会自动发一封。

## 两个容易踩的时间坑（已处理）

**跨年**：原文只写「1月5日」不写年份时，按「比当前月份早半年以上算次年」推断。12 月发的寒假注册通知写「1月5日」，不会被当成已经过去的日期而丢掉。写给读者看的时间仍按原文写法，不擅自补年份。

**条数上限**：每栏每轮最多处理 6 条，是防止单次任务超时的限额。超出的保持未读，下一轮接着处理，不会丢。已读记录只在判定完成后才写入，抓取失败的下轮还会再来。

## 想加别的栏目

改 `config.json`，加一条：

```json
{
  "name": "学生科技",
  "url": "https://spxy.zjgsu.edu.cn/?xskj.html",
  "enabled": true
}
```

- 地址必须是**栏目列表页**，不是文章页
- `enabled: false` 可以不删但暂停检查
- 新加的栏目第一次检查时只登记已有链接、不推送历史，从第二次才开始推新的
- `max_new_per_site` 控制每次最多抓几条（默认 6，防止一次抓太多导致任务超时）

## 判断口径（写死在 screener.js 里）

**保留**：竞赛、教务考试、选课学籍、评奖资助、缴费注册、实习就业、保研考研、交流交换、科研创新、论文答辩、实验安全、讲座报告、党团实践、安全后勤、健康医保、证件考试、毕业离校、其他重要

**忽略**：社团招新、节日问候、纯获奖喜报、活动总结、新闻稿、已过期通知、商业广告、校外培训推销、面向教职工的事务

**时间显示**：
- 有区间就写区间，报名时间也保留
- 一条里有多个时间段时并列，每段标出是什么时间
- 例：`报名 11月1日 — 11月10日；初赛 11月15日；决赛 11月25日`

## 常见问题

**网页打不开？**
GitHub Pages 首次部署要等 1~2 分钟；路径必须是 `/docs`，分支必须是 `main`。

**没收到邮件？**
先看 Actions 日志里有没有「邮件已发送」。如果报 authentication error，是授权码错了或没用授权码。

**Actions 报错 `npm install` 失败？**
重跑一次即可，多半是网络抖动。

**数据会不会丢？**
所有通知都存在 `data/notices.json` 里，跟着仓库走，GitHub 有完整历史。想备份就下载这个文件。

**能不能删掉某条？**
在 GitHub 上直接编辑 `data/notices.json`，删掉那一条的对象，提交即可；下次生成网页时它就不见了。

## 手动推送

网页「留档库」里每条记录右下角有 **推送** 按钮，点一下就把这一条的提炼结果单发一封邮件；「推送与设置」页的 **立即推送** 可以一次推最新 N 条。

两个按钮都要先填 GitHub Token（只需一次，存在浏览器本地）：

1. GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token
2. Repository access 只选你这个仓库
3. Permissions 只勾 **Actions: Read and write**
4. 把生成的 `ghp_...` 填进「推送与设置」页的输入框

按钮实际是调用 GitHub Actions 发信，所以按的时候电脑不用开，手机点也行。

也可以不用网页，直接在仓库 Actions 页面手动运行 `手动推送留档` 这个任务，条数填 1、url 填要推的那条。
